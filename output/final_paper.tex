\begin{abstract}
We present an evolved ES-FA framework that unifies hardware-aware SNN training, estimator-guided co-design, local FPGA implementation validation, and adaptive runtime execution. The system preserves the original ES-FA foundation while introducing reproducible manifests, local xsim and Vivado Tcl-driven evidence generation, and explicit static-vs-adaptive execution comparisons. The framework emits standardized software and hardware artifacts for baseline-vs-optimized analysis, dense-vs-event scheduling analysis, estimator-vs-hardware correlation, and adaptive-vs-static evaluation.
\end{abstract}

\section{Introduction}
Energy-limited edge inference needs sparse, event-driven compute paths aligned with neuromorphic principles. ES-FA targets this by co-optimizing SNN training and hardware proxies, then validating design choices through FPGA-centered reporting.

\section{Background}
Directly trained SNNs offer sparsity-driven efficiency but require robust training methods and hardware mapping methodology. ES-FA combines surrogate-gradient training with software estimators and FPGA scheduler comparisons.

\section{Method}
The method integrates:
\begin{itemize}
\item config-driven SNN training with run manifests and exportable INT8 artifacts,
\item estimator APIs for spike, memory, energy, and latency proxies,
\item experiment and iteration loops with stable logging.
\end{itemize}

\section{System Architecture}
ES-FA includes:
\begin{itemize}
\item software layer: training, experiments, analysis;
\item hardware layer: dense/event scheduler RTL and top-level integration;
\item runtime layer: intent engine, task router, adaptive policy, CLI.
\end{itemize}
Adaptive execution selects dense or event scheduling from workload sparsity and logs every decision.

\section{Experiments}
Experiments cover baseline training, hardware-aware loss shaping, sparsity control, temporal multiplexing effects, quantization impacts, and adaptive dataflow. Iterations v1--v3 refine combinations under a fixed metrics schema.

\section{Results}
Results are emitted as:
\begin{itemize}
\item raw software tables (\texttt{raw\_software\_metrics.csv}),
\item raw hardware tables (\texttt{raw\_hardware\_metrics.csv}),
\item percentage-change comparisons (\texttt{percentage\_change\_table.csv}),
\item short interpretations (\texttt{interpretations.md}).
\end{itemize}
The reporting enforces absolute baseline and optimized values with percentage change for each claim.

\section{Hardware Validation}
Hardware validation follows:
\begin{enumerate}
\item xsim regression for dense and event scheduler modes,
\item Vivado batch builds (\texttt{vivado -mode batch -source build.tcl}),
\item synthesis/implementation/timing report parsing into normalized JSON.
\end{enumerate}
All \texttt{.rpt} and \texttt{.log} files are persisted per model and mode under \texttt{results/hardware\_validation}.

\subsection{Current Local FPGA Metrics}
For the validated model matrix (baseline + adaptive run variants at 100 MHz target), the local implementation reports yield:
\begin{itemize}
\item Latency: 5760 ns (active window), Cycle count: 576
\item LUT usage: 22,193; BRAM usage: 0; DSP usage: 0
\item Worst negative slack (WNS): -0.92 ns; estimated Fmax: 91.58 MHz
\end{itemize}

These measurements are generated from Vivado implementation reports and xsim traces, and are treated as local hardware evidence prior to final KV260 physical board runs.

\section{Discussion}
Compatibility-first refactoring preserved working code while adding reproducibility and system-level orchestration. Explicit policy logs and hardware report normalization improved interpretability and auditability.

\section{Limitations and Future Work}
Current local validation relies on implementation reports and simulation-derived cycle/latency estimates. Final KV260 board measurements are required for full physical characterization and will be integrated into the same schema.

\section{Conclusion}
The evolved ES-FA framework transitions from isolated components to a research-grade, system-level pipeline with measurable software-hardware evidence, adaptive runtime behavior, and publication-ready documentation.
